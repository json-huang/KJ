流程编辑：继续完善的方向

我已定位到现有实现：WorkflowEditorPage（Canvas 拖拽 + 连接下一步）+ WorkflowEditorViewModel + WorkflowJsonStore（LocalAppData JSON 持久化）。下面请你选一个“优先成熟目标”。

A · 交互与稳定性优先（推荐先做）
  • 拖拽/选中/对齐/缩放更顺手
  • 自动保存、撤销重做、脏数据提示
  • 校验：孤儿节点/循环/缺参数
  • 节点类型选择器（读/写/等待/条件…）

把“编辑器体验”做成熟

目标是：日常编辑不崩、好用、可回滚；保存出来的 JSON 结构稳定可演进。

B · 流程表达能力优先
  • 分支/条件（True/False）
  • 多出口连线（不是只支持 NextStepId）
  • 子流程/复用
  • 版本管理与迁移

让流程“能表达现场逻辑”

目标是：先把模型做对，UI 跟上；后续运行引擎更容易落地。

C · 运行与调试优先
  • 一键运行 / 单步 / 暂停 / 继续
  • 运行日志与当前节点高亮
  • 参数面板：运行时值、读写结果
  • 失败重试/超时/告警联动

从“可编辑”到“可运行可追溯”

目标是：先做一条最小可用的运行闭环，再逐步增强节点类型与可靠性。

已观察到的“不成熟点”（现状）

  • 目前连线仅支持 NextStepId；缺少分支/多出口模型
  • 画布节点是“命令式渲染”，交互扩展（框选/对齐/缩放）需要补齐
  • 保存是手动按钮；缺少脏状态、自动保存、撤销重做
  • 缺少结构校验与错误提示（例如循环、断链、缺参数）
